# Host labels across virus–host prediction tools — one figure, end to end

This tree contains exactly what is needed to produce one figure and nothing
else:

![The host scheme](host_general_scheme_R.png)

Sixteen published virus–host prediction tools name their hosts differently.
One writes `human`, another `Homo sapiens`, a third `Homo sapiens (taxid 9606,
positive class)`. One counts sequence records, another virus taxa, another
protein-family profiles. This repository harmonizes their host labels into a
single vocabulary of 50 display categories and draws the result.

## Reproduce it

```bash
conda create -y -n host-scheme python=3.12
conda activate host-scheme
pip install -r requirements.txt
CONDA_SUBDIR=osx-64 conda env create -p ~/.local/share/hosts-renv -f environment-R.yml

RENV=~/.local/share/hosts-renv python audit_all.py
```

`audit_all.py` rebuilds every table and the figure and checks each step: 15
stages, about a minute. `--no-render` skips the one stage that needs R. R is
used for two things only, rendering the figure and reading DeePaC-vir's `.rds`
labels. The raw files are not distributed; without them under `raw_sources/`
the four stages that read them are skipped and the rest runs from the committed
per-tool counts. With them, the run also proves those counts reproduce.

Every table is written twice: the `.csv`, which every script reads and
verifies, and an `.xlsx` copy with the same name for reading
(`scripts/export_tables_xlsx.py`, the last stage).

## HostClassifier is kept but excluded

HostClassifier was removed from the review after closer inspection of its
released materials, so it is out of this analysis. Its raw files, recomputed
counts and curation rows stay in the tree: it carries `include_in_analysis = no`
in `scripts/tool_metadata.csv`, and `categories.excluded_instances()` is the one
place that reads the flag. Every builder drops its rows through that function,
so the exclusion is a rule rather than a gap in the files.

Because the standalone-species bar is a count rather than a share, it tightens
when the corpus shrinks. With 17 dataset instances it is 5, which keeps the same
26 standalone species, the same 50 categories and all nine wildlife reservoirs
that the bar exists to keep; at 6 of 17 all nine would fall out. The default
lives in `scripts/build_general_scheme.py`.

## Inputs, outputs and working notes

Four tables in `scripts/` are maintained by hand and are the only place a
judgement is recorded: `tool_metadata.csv` (the tools, their endpoints and the
include_in_analysis flag), `label_enrichment.csv` and `label_categories.csv`
(one curation row per released label) and `host_name_authority_checks.csv`.
Everything else with a `.csv` extension in that folder is generated by the
pipeline and is overwritten on every run.

`archive/` holds the audit logs and the superseded matplotlib draft of the
figure. Nothing there is read by any script.


## The chain

```
raw_sources/<Tool>/          18 extractors        counts_per_tool_v2/*.csv
        │                                              │
        │  verify_raw_sources.py (SHA-256)             │  verify_against_committed.py
        ▼                                              ▼
build_master_labels.py   ──► master_labels.csv                 8,076 label records
build_species_matrix.py  ──► species_matrix.csv                1,513 host entities
build_general_scheme.py  ──► general_scheme_matrix.csv         50 display categories
        ▼
export_general_scheme_for_r.py ──► scripts/r_general_scheme/   matrix, row and column
        ▼                                                      meta, cell flags, palette,
make_general_scheme_heatmap.R  ──► host_general_scheme_R.png   icons
```

The R script does no harmonization. It is handed the matrix, the row order, the
flags and the palette and draws them, which is why it cannot disagree with the
tables about a number. `make_general_scheme_heatmap.py` draws the same matrix
with matplotlib as a cross-check, and the exporter imports its data functions.

## How the numbers are kept honest

- **Every raw file is identified by SHA-256.** 34 of 34. All carry a resolvable
  URL, and 19 have been re-fetched and confirmed identical to the published
  copy.
- **The counts reproduce byte for byte** from the raw files, checked on every
  run.
- **Every drawn cell is re-derived** from `species_matrix.csv` and the routing
  table and compared with what the figure was handed.
- **95 numerical claims** in the manuscript text are recomputed from the
  committed tables by `verify_reported_numbers.py`, which also scans the
  manuscript files for values left over from earlier builds and fails on them.

## What counting units mean here

The instances do not count the same thing: ten count sequence records, five
count virus taxa, one a deduplicated species pool, and one (VPF-Class) counts
protein-family profiles, which are not viruses at all. **Absolute counts are
therefore not comparable horizontally between columns.** Nothing in the Results
sums observations across instances. The single figure that does span them,
603,953 total source observations, is used only as a processing checksum on the
routing step, and is not a corpus size.

## Not redistributed

The tools' raw files are third-party data and stay out of git; the manifest says
where each came from. The articles are the publishers' copyright and are not
here either; their DOIs are in the manifest and in Table S1.
